# WMS — система адресного складського обліку (курсова робота)

Node.js (Express) + PostgreSQL. Реалізує схему БД з лабораторних 2-4 (OLTP + OLAP)
для системи складського обліку (WMS).

- Бенедюк Ярослав Миколайович — backend, БД, тести, Docker
- Прасол Максим Олександрович — документація, OLAP-звіти, ERD

Деталі внесків — у `CONTRIBUTIONS.md`.

## Технологічний стек

- Мова: Node.js 20 (JavaScript)
- Веб-фреймворк: Express 4
- БД: PostgreSQL 16
- SQL Builder: Knex.js 3 (параметризовані запити, транзакції через `db.transaction()`)
- Шаблонізатор: EJS 3
- Тести: Jest 29
- Контейнеризація: Docker / Docker Compose

Використано Knex.js як SQL builder: CRUD і транзакції реалізовані через builder API,
складні аналітичні запити (OLAP) — через `knex.raw()` з параметризованим SQL.
Це забезпечує захист від SQL-ін'єкцій і контроль над запитами.

## Запуск (Docker Compose — рекомендовано)

```bash
docker-compose up -d
```

Сервіси:
- Додаток: http://localhost:3000
- pgAdmin: http://localhost:8080 (root@kpi.edu / password123)
- PostgreSQL: localhost:5432 (postgres / password123, БД `logistics`)

Схема та тестові дані завантажуються автоматично з `db/schema.sql`.

## Запуск (локально)

1. Встановити залежності: `npm install`
2. Створити базу `logistics` і виконати `db/schema.sql`.
3. Скопіювати `.env.example` → `.env`, вказати `DATABASE_URL`.
4. Запустити: `npm start` (або `npm run dev`).

## Запуск тестів

```bash
npm test
```

Тести використовують `TEST_DATABASE_URL` або `DATABASE_URL` і відкочують зміни
через `ROLLBACK` після кожного тесту. Потрібна завантажена схема `db/schema.sql`.

## Структура проєкту

- `docker-compose.yml`, `Dockerfile` — контейнеризація
- `db/schema.sql` — агрегована схема БД + тестові дані
- `migrations/` — інкрементальні міграції
- `docs/adr/` — специфікація, ADR, ER-діаграма, тести обмежень
- `docs/schema.md` — документація схеми БД
- `docs/queries.md` — складні аналітичні запити
- `docs/lab3/`, `docs/lab4/` — звіти та SQL-скрипти лабораторних
- `src/server.js` — Express-сервер (CRUD, оприбуткування, переміщення/списання, звіти)
- `src/db.js` — підключення до PostgreSQL
- `views/` — EJS-шаблони
- `test/integration/` — інтеграційні тести БД

## Функціонал

- Довідники: товари, постачальники, комірки складу (CRUD).
- Накладні постачання: створення, позиції, оприбуткування, скасування, видалення.
- Залишки по комірках, журнал переміщень і списань.
- Аналітичні звіти (OLAP): агрегація, GROUP BY, HAVING, JOIN, підзапити,
  багатотаблична агрегація, віконні функції, товари нижче мінімуму.
- Контроль місткості комірок і наявності залишку на рівні застосунку (транзакції).
- Оптимістичне блокування при оновленні постачальників (колонка `version`).
- Soft delete для постачальників (колонка `deleted_at`, кнопка "Деактивувати").

## Приклади використання

1. Відкрити http://localhost:3000 — дашборд з показниками.
2. `/products`, `/suppliers`, `/locations` — довідники (CRUD).
3. `/orders` → "Нова накладна" → додати позиції → "Оприбуткувати" (оновлює залишки).
4. `/movements/new` — переміщення/списання з перевіркою залишку і місткості.
5. `/reports` — аналітичні звіти (OLAP).
